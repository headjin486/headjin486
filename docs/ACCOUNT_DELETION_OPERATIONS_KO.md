# MY EARTH 외부 계정 삭제 요청 처리 절차 (운영 초안)

작성일: 2026-11-22  
대상: https://headjin486.github.io/headjin486/delete-account.html  
문의 이메일: headjin486@gmail.com

> 현재 외부 웹 경로는 이메일 요청을 접수하는 수동 방식이다. 자동 삭제 시스템이 아니다. 운영자가 실제로 처리할 수 있는지 확인하고 처리 기한을 확정한 뒤 공개 페이지와 Play Console에 반영한다.

## 1. 요청 접수

1. 사용자가 공개 삭제 페이지의 이메일 링크를 통해 요청을 보낸다.
2. 요청에 Google 계정 이메일을 기재하도록 안내한다. Firebase UID는 사용자가 알고 있는 경우에만 받는다.
3. 비밀번호, 인증 코드, 복구 코드 또는 결제정보를 요청하지 않는다.
4. 요청 접수 시각과 처리 상태를 내부 기록한다. 내부 기록에는 삭제 처리에 필요한 최소 정보만 보관한다.

## 2. 계정 소유 확인

1. 요청 이메일 주소와 Firebase Authentication에 등록된 Google provider 이메일을 대조한다.
2. 이메일이 일치하지 않거나 계정이 확인되지 않으면 삭제하지 않는다.
3. 불일치 시 Firebase 계정에 연결된 이메일 주소로 추가 확인을 요청한다.
4. 소유 확인이 완료되기 전에는 어떠한 계정이나 백업도 삭제하지 않는다.

## 3. Firebase 데이터 삭제

Firebase Console에서 대상 Firebase UID를 정확히 확인한 뒤 다음 순서로 처리한다.

1. Authentication > Users에서 해당 UID 및 이메일을 다시 대조한다.
2. Firestore Database에서 `exploration_backups/{UID}/chunks` 컬렉션의 모든 문서를 확인한다.
3. 해당 UID의 `chunks` 하위 문서를 모두 삭제한다. 컬렉션이 비었는지 재확인한다.
4. 다른 사용자 UID의 문서가 영향을 받지 않았는지 확인한다.
5. Firestore 백업 삭제가 확인된 뒤 Authentication의 해당 사용자 계정을 삭제한다.
6. 삭제가 완료된 UID, 처리 일시, 성공 여부만 내부 처리 기록에 남긴다. 백업 payload나 GPS 정보를 별도 복사해 보관하지 않는다.

중요:
- 계정 삭제 전 Firestore UID가 정확히 일치하는지 반드시 확인한다.
- 사용자의 로컬 GPS 기록과 지도 데이터는 서버에서 삭제할 수 없다. 앱 내부 삭제는 클라우드 계정/백업 삭제와 별개다.
- Firestore의 추가 경로 또는 새 데이터 구조가 생기면 이 절차를 먼저 갱신한다.

## 4. 완료 회신

1. 삭제 요청자에게 Firebase 계정과 클라우드 백업 삭제 완료 여부를 이메일로 회신한다.
2. 로컬 기기 데이터는 별도임을 다시 안내한다.
3. 실패 또는 계정 확인 불가 시 그 사유와 사용자가 취할 조치를 안내한다.

## 5. 공개 전 확정할 운영 기준

- [ ] 운영 담당자 및 부재 시 대체 담당자
- [ ] 요청 접수 확인 회신 목표 시간
- [ ] 계정 소유 확인이 끝난 뒤 삭제 완료 목표 기한
- [ ] 요청·완료 기록의 최소 보유 기간과 안전한 폐기 방식
- [ ] Firebase Console에서 실제 테스트 계정으로 전체 절차 리허설
- [ ] 개인정보처리방침과 삭제 페이지의 처리 기한 문구 일치
- [ ] Play Console에 외부 삭제 URL을 등록하기 전 링크 및 메일 수신 테스트

## 6. 운영상 주의

- 이 절차는 수동 운영이므로 “즉시 자동 삭제”라고 광고하거나 표시하지 않는다.
- 사용자의 비밀번호나 인증 코드를 이메일로 받지 않는다.
- 삭제 전후의 계정 이메일과 UID는 접근이 제한된 운영 환경에서만 확인한다.
- 삭제 완료 후에는 법적 의무가 없는 한 계정·백업 내용을 재보유하지 않는다.
