# MY EARTH Firebase 백업 설계

## 제품 원칙
- MY EARTH는 걷기 경쟁이나 순위 앱이 아니다. 글로벌 TOP 30, 공개 랭킹, 닉네임 경쟁 기능은 구현하지 않는다.
- 핵심 데이터는 사용자가 직접 해금한 개인 지도다.
- 휴대폰 SQLite가 즉시 사용 가능한 로컬 기준 데이터이며, Firestore는 기기 변경·재설치 복구용 백업이다.
- Firebase Spark 무료 요금제로 시작한다. Blaze 전환, Cloud Functions, 결제 계정 연결은 별도 승인 전까지 하지 않는다.

## 인증 방식
1. 최초 실행 시 Firebase 익명 인증으로 UID를 자동 발급한다. 별도 회원가입 화면 없이 앱을 바로 사용할 수 있다.
2. 익명 UID에 연결된 백업은 현재 설치본에서 자동 동기화한다.
3. 사용자가 원할 때 Google 계정을 기존 익명 계정에 linkWithCredential 방식으로 연결한다. 새 UID로 별도 계정을 만들지 않는다.
4. 기기 변경·재설치 후에는 Google 로그인으로 기존 UID에 접근해 백업을 복구한다.
5. Google 연결 전 앱 데이터 삭제·기기 분실 시 익명 계정 복구가 불가능할 수 있음을 앱에서 명확히 안내한다.

## 백업 데이터 범위
- 백업 대상: 현재 SQLite explored_cells 테이블의 5m 격자 식별자 (cell_x, cell_y)만.
- 백업 제외: GPS 원본 좌표, 시간순 이동 경로, 마지막 위치, 전화기 식별자, 광고 식별자.
- 현재 TrackStore의 격자는 5m 투영 좌표계다. 이전 설계 문서의 11km 격자 설명은 폐기한다.
- 데이터는 버전이 포함된 압축 청크로 저장한다. 청크 크기는 Firestore 문서 제한보다 충분히 작게 유지한다.
- 경로 기록 points는 클라우드로 전송하지 않는다.

## Firestore 구조
exploration_backups/{uid}/chunks/{chunkId}
- formatVersion: 백업 포맷 버전
- payload: 압축된 격자 셀 식별자
- updatedAt: 서버 타임스탬프

UID 경로 소유자만 읽기·쓰기·삭제 가능하도록 보안 규칙을 제한한다. 공개 컬렉션과 랭킹 컬렉션은 만들지 않는다.

## 동기화·복구 규칙
- 로컬 탐험은 네트워크·인증 상태와 무관하게 계속 동작해야 한다.
- 온라인 상태에서 백업을 비동기 수행하고 실패하면 다음 실행/재연결 때 재시도한다.
- 새 기기에서는 클라우드 셀을 내려받아 로컬 셀과 합집합으로 병합한다.
- 로컬 DB를 클라우드 백업으로 덮어쓰지 않는다. INSERT OR IGNORE로 병합하고 면적 통계는 실제 셀을 기준으로 다시 계산한다.
- 동기화는 중복 실행되지 않도록 잠금/작업 큐를 둔다.
- 동기화 중 GPS 원본 좌표나 시간순 기록을 로그에 남기지 않는다.

## 계정 연결·삭제
- Google 연결은 반드시 기존 익명 Firebase 사용자에 계정 연결 방식으로 수행한다.
- 이미 다른 Firebase 계정에 연결된 Google 계정이면 자동 병합하지 않는다. 데이터 충돌 가능성을 설명하고 안전한 복구 절차를 별도로 제공한다.
- 계정 삭제 기능은 Firebase 사용자 삭제와 해당 UID의 모든 백업 청크 삭제를 함께 처리해야 한다.
- 계정 삭제·클라우드 데이터 삭제는 출시 전 필수 항목이다.

## 보안·비용
- Firestore Rules Emulator 테스트에서 비로그인/타 UID 접근 거부, 문서 필드 검증, payload 크기 제한을 확인한다.
- Firebase App Check는 Play Integrity 기반으로 출시 전 적용한다. 개발 테스트는 debug provider로 분리한다.
- Spark 무료 사용량을 모니터링하고 한도 초과 위험 시 동기화 빈도를 제한한다.
- Blaze 자동 전환 또는 결제 설정은 하지 않는다.

## 구현 순서
1. Firebase Android 설정 및 빌드 연결 확인
2. 익명 인증 자동 생성과 세션 유지
3. 5m 해금 셀 백업 업로드·다운로드·합집합 복구
4. 오프라인 재시도와 중복 동기화 방지
5. 기존 익명 UID를 유지하는 Google 계정 연결
6. Google 로그인 후 새 기기 복원 실기기 검증
7. 계정/클라우드 데이터 삭제, 개인정보 처리방침 및 Play Data safety 검증
